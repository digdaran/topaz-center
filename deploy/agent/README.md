# Агент АЗС: установка

**Требования:** Windows 10/11 или Server 2016+ x64 (для 32-битных систем есть сборка `win-x86`). **Windows 7 не поддерживается** — это ограничение .NET 8. Устанавливать .NET не нужно: агент поставляется одним exe-файлом. Нужен доступ к Firebird Топаза (обычно `127.0.0.1:3050`) и исходящий HTTPS к серверу.

Агент **только читает** базу Топаза: все запросы — `SELECT` в read-only транзакции. Входящих портов он не открывает.

## Установка

1. Скачайте `TopazAgent-<версия>-win-x64.zip` (для 32-битной Windows — `win-x86`) со страницы [Releases](https://github.com/digdaran/topaz-center/releases/latest) и распакуйте во временную папку.
2. Откройте PowerShell **от имени администратора** в распакованной папке `TopazAgent-<версия>-win-x64`:

```powershell
# необязательно: сверить контрольную сумму с SHA256SUMS.txt из релиза
Get-FileHash ..\TopazAgent-*-win-x64.zip -Algorithm SHA256
# снять пометку «скачано из интернета», иначе PowerShell может не запустить скрипт
Get-ChildItem -Recurse | Unblock-File
Set-ExecutionPolicy -Scope Process Bypass
.\install.ps1 -StationName "АЗС-5 Северная"
```

**Подключение к серверу.** Ключи не нужны: в конце установки агент отправляет заявку на сервер и показывает **код подтверждения**, например `K7Q4-9MXD`.
1. Сообщите код администратору сервера по телефону или в мессенджере.
2. Администратор сверит код и одобрит заявку в разделе «АЗС → Подключение».
3. В течение минуты агент получит доступ и отправит всё, что успел собрать с момента установки. До одобрения данные копятся на этом ПК, ничего не теряется.

Код можно посмотреть снова: `& "C:\Program Files\TopazAgent\TopazAgent.exe" check`. Если заявка истекла (14 дней) или была отклонена, агент сам пришлёт новую с новым кодом (после отклонения — через сутки).

**Значения по умолчанию** (меняются параметрами):
- сервер — `https://topaz.08u.ru` (`-ServerUrl`; при обновлении сохраняется прежний адрес);
- пароль Firebird — стандартный пароль Топаза (`-FirebirdPassword`). Если Firebird его не принял, установщик попросит ввести пароль (до 3 попыток). Пароль хранится только в переменных окружения службы, в `appsettings.json` и логи не попадает. Он записан в `install.ps1`, а репозиторий публичный: это допустимо, пока Firebird на АЗС доступен только локально (`127.0.0.1:3050`) — не открывайте порт 3050 наружу;
- база Топаза — ищется сама (см. ниже).

**Где скрипт ищет базу Топаза** (если не указан `-DatabasePath`):
1. при обновлении — путь из прежней установки;
2. в стандартной папке `C:\Program Files (x86)\TopazAZS-*\TopazAZS.fdb` (и в `C:\Program Files\TopazAZS-*` на 32-битной Windows). Если найдено несколько баз, скрипт покажет список и попросит выбрать номер (по умолчанию самая свежая);
3. если ничего не найдено — попросит ввести путь к `TopazAZS.fdb` (можно вставить с кавычками из «Копировать как путь»).

Указать путь явно: `-DatabasePath "D:\Topaz\TopazAZS.fdb"`. Если Firebird стоит на другом компьютере (`-FirebirdHost`), путь не ищется: укажите его так, как он виден на том компьютере, или алиас Firebird.

Скрипт:
- копирует агент в `C:\Program Files\TopazAgent`;
- записывает `appsettings.json` (без секретов);
- сохраняет пароль Firebird как переменную окружения только этой службы;
- закрывает папку состояния `%ProgramData%\TopazAgent` для всех, кроме SYSTEM и администраторов;
- регистрирует службу `TopazAgent` (автозапуск, перезапуск при сбое);
- выполняет `check` и запускает службу.

Название АЗС лучше давать понятное и уникальное: так администратору проще опознать заявку. При одобрении его можно поправить.

`TopazAgent.exe` не подписан цифровой подписью, поэтому при ручном запуске Windows SmartScreen может показать предупреждение («Подробнее → Выполнить в любом случае»). Службу это не затрагивает.

Дополнительные параметры: `-ServerUrl`, `-DatabasePath`, `-FirebirdPassword`, `-FirebirdHost`, `-FirebirdPort`, `-FirebirdUser`, `-TimeZone` (например, `"Ekaterinburg Standard Time"`; по умолчанию берётся пояс Windows).

## Команды

```powershell
& "C:\Program Files\TopazAgent\TopazAgent.exe" check          # конфиг, БД Топаза, связь с сервером, регистрация
& "C:\Program Files\TopazAgent\TopazAgent.exe" status         # очередь, курсоры, dead-letter
& "C:\Program Files\TopazAgent\TopazAgent.exe" requeue-dead   # вернуть отклонённые пакеты в очередь
Get-Content "$env:ProgramData\TopazAgent\logs\agent-$(Get-Date -f yyyyMMdd).log" -Tail 50
```

`check` и `status` читают те же переменные окружения, что и служба. При ручном запуске `check` после установки задайте их в сессии (`$env:TOPAZ_AGENT_Firebird__Password = '...'`).

## Автообновление

Начиная с версии 1.2 агент обновляется сам. Новая версия приходит вместе с обновлением сервера (`setup.sh`), доступ АЗС к GitHub не нужен.

1. Сервер предлагает новую версию в ответ на heartbeat — по правилам раскатки из раздела **АЗС → Обновление агентов**: сначала пилотные АЗС, остальные позже.
2. Агент скачивает пакет со своего сервера и проверяет **цифровую подпись**. Пакеты подписываются при сборке на GitHub ключом, которого на сервере нет, а открытый ключ встроен в агент. Поэтому даже взломанный сервер не сможет подсунуть агенту чужой exe.
3. Агент распаковывает пакет в `%ProgramData%\TopazAgent\updates\<версия>` и запускает установщик одноразовой задачей планировщика от имени SYSTEM (`TopazAgentUpdate`).
4. Установщик:
   - останавливает службу;
   - сохраняет прежние файлы в `updates\backup`;
   - копирует новые: `appsettings.json` и пароли не трогаются, `datasets.json` заменяется, а прежний сохраняется как `datasets.json.bak`;
   - запускает службу.
5. Если новая версия за 3 минуты не вышла на связь с сервером, установщик **возвращает прежнюю версию**. Сервер показывает ошибку, а в «Контроле» появляется событие. Неудачную версию агент пробует снова не чаще раза в сутки, всего до 3 раз.

Очередь данных при обновлении не теряется. Служба стоит меньше минуты, данные за это время остаются в Топазе и будут прочитаны.

- Журнал установки: `%ProgramData%\TopazAgent\logs\update-<версия>.log`.
- Отключить автообновление на одной АЗС: на сервере группа «не обновлять» или локально `TOPAZ_AGENT_Updates__Enabled=false`.

**Агенты 1.0 и 1.1 автообновления не умеют:** их один раз нужно обновить вручную до 1.2 или новее, дальше обновления придут сами.

## Что агент сообщает о ПК АЗС

С версии 1.2.1 агент вместе с heartbeat присылает (раздел **АЗС**, столбец «ПК АЗС»):
- свободное и общее место на диске с базой Топаза и на системном диске;
- размер файла базы Топаза — только по данным файловой системы, сам файл не открывается;
- время на ПК и часовой пояс Windows. Сервер сравнивает их с точным временем: Топаз записывает время операций по этим часам;
- время работы Windows и версию ОС.

Данных продаж, паролей и содержимого файлов среди этого нет. Если базы нет на этом ПК (Firebird на другом компьютере или указан алиас), её размер и диск не сообщаются.

## Обновление вручную и переустановка

- **Обновление вручную:** запустите `install.ps1` новой версии с теми же параметрами. Очередь и состояние сохраняются. Изменённый `datasets.json` не перезаписывается, новая версия кладётся рядом как `datasets.json.new`.
- **Переустановка на другой ПК или с чистым состоянием:** установите агент как обычно. Придёт новая заявка — администратор одобряет её как «существующая АЗС». История сохранится, прежний доступ перестанет действовать, агент перечитает данные, а сервер не создаст дублей.
- **Удаление:** `.\uninstall.ps1` (с `-RemoveState` удаляется и локальная очередь).

## Настройки (`appsettings.json`)

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `Collection:IntervalSeconds` | 60 | период чтения смен и журналов |
| `Collection:SnapshotIntervalSeconds` | 900 | период чтения справочников |
| `Collection:ClosedSessionsWindow` | 3 | сколько последних закрытых смен перечитывать каждый цикл |
| `Collection:FullRescanHours` | 24 | полный перепроход всех смен (уходят только изменения) |
| `Collection:MaxItemsPerBatch` | 500 | строк в пакете |
| `Collection:MaxQueueBytes` | 2 ГБ | выше этого сбор на паузе (данные остаются в Топазе) |
| `Server:RetryMaxSeconds` | 900 | максимальная пауза между повторами |

Любой ключ можно переопределить переменной окружения `TOPAZ_AGENT_<Секция>__<Ключ>`.
