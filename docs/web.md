# Веб-интерфейс Topaz Center

Интерфейс открывается по адресу сервера (`https://<домен>/`) и работает в браузере и на телефоне. Данные обновляются примерно раз в минуту, с задержкой связи агента.

## Организации

На одном сервере работают несколько хозяев АЗС — **организаций** (с версии 1.5). Организация видит только свои АЗС и всё, что к ним относится:
- данные, отчёты, выгрузки, события «Контроля»;
- своих пользователей и свой журнал действий;
- свои чаты Telegram и свои пороги правил;
- свою себестоимость «для всех АЗС» и подсказки справочника топлива, выученные на своих АЗС.

Организации ведёт суперадминистратор в **Настройки → Организации**: создать, переименовать, отключить (пользователи организации не смогут войти, АЗС продолжат передавать данные). Новую АЗС он относит к организации при одобрении заявки, существующую может передать другой организации (**АЗС → Состояние и настройки**, меню АЗС; история уходит вместе с ней).

Суперадминистратор не входит ни в одну организацию: данные он смотрит, выбрав организацию в шапке, сводного режима нет. Каждое переключение пишется в журнал.

При обновлении до 1.5 всё существующее попадает в организацию «Основная».

Граница проходит в двух местах: каждый запрос интерфейса ограничен АЗС организации (`StationScope`), а база дополнительно не отдаёт чужие строки (row level security, см. [architecture.md](architecture.md#9-безопасность)).

## Вход и роли

| Роль | АЗС | Что доступно |
|---|---|---|
| **Суперадминистратор** | выбранной в шапке организации | всё, что владелец, плюс платформа: **организации**, **подключение АЗС** (одобрение заявок, блокировка, перевыпуск доступа, передача АЗС), **обновление агентов**, **общий справочник видов топлива**, пользователи и журнал всех организаций, чаты Telegram платформы |
| **Владелец** | все АЗС своей организации | себестоимость, финансы, планы, сопоставление топлива, пороги правил и уведомления организации, настройки АЗС, пользователи и журнал своей организации |
| **Управляющий** | назначенные в своей организации | аналитика с маржой, ввод себестоимости своих АЗС, планы, настройки резервуаров |
| **Просмотр** | назначенные в своей организации | все отчёты без себестоимости и маржи (сервер эти поля не отдаёт вовсе) |

Первый пользователь (суперадминистратор) создаётся при установке: переменные `TOPAZ_BOOTSTRAP_OWNER_LOGIN/PASSWORD` в `.env` или команда
`docker compose exec central dotnet Topaz.Central.dll create-user --login admin --role superadmin`.
Последнего суперадминистратора нельзя понизить или отключить; назначает суперадминистраторов только суперадминистратор.
Остальных пользователей заводят в разделе **Настройки → Пользователи**: владелец — в своей организации, суперадминистратор — в любой.

**Защита:**
- пароль не короче 10 символов;
- после 5 неудачных попыток (пароля или кода) вход блокируется на 15 минут; лимит 20 попыток входа в минуту с адреса, 600 запросов API в минуту на пользователя (`Topaz__LoginsPerMinutePerIp`, `Topaz__UiRequestsPerMinute`);
- сессия живёт 12 часов, при смене пароля, роли, включении/сбросе двухфакторной защиты или отключении пользователя она сразу закрывается; cookie только по HTTPS (`Topaz__SecureCookies`);
- **двухфакторный вход** (TOTP, RFC 6238: 6 цифр, 30 с, допуск ±1 шаг, каждый код один раз): `POST /auth/login` отвечает `need_code: true` и ставит зашифрованный билет на 5 минут (cookie `topaz_ui_2fa`), сессию выдаёт `POST /auth/login/code`. Включение: `POST /auth/totp/setup` (пароль → секрет и `otpauth://`), `POST /auth/totp/enable` (первый код → 8 запасных кодов, хранятся SHA-256). Секрет зашифрован ключами Data Protection (том `keys`: без него коды не проверить, поможет `reset-totp`). Для суперадминистратора обязателен (`Topaz__RequireTotpForSuperadmin`): пока не включён, отвечает только `/auth/*`, остальное — 403 `totp_setup_required`. Сброс: владелец/суперадминистратор в карточке пользователя (`reset_totp`) или `docker compose exec central dotnet Topaz.Central.dll reset-totp --login <логин>`;
- все изменения пишутся в журнал действий.

## Общий фильтр

На каждой странице есть фильтр:
- выбор АЗС (по умолчанию все доступные);
- период — даты по местному времени каждой АЗС;
- детализация: час, день, неделя, месяц;
- сравнение: с предыдущим периодом такой же длины или с тем же периодом год назад;
- вид топлива — из эталонного справочника (см. ниже), а не название в Топазе: «Аи92» одной АЗС и «АИ-92» другой попадают в один вид;
- способ оплаты — наличные, банковские карты, по договору, топливные карты (параметр `pay`).

Фильтр хранится в адресной строке, поэтому ссылку можно переслать. **Отчёты за период режут по времени операции, а не по сменам** — так же, как экспорт Топаза за период.

## Разделы

| Раздел | Что показывает |
|---|---|
| **Обзор** | главные показатели с динамикой к периоду сравнения, выручка и литры по дням, структура продаж топлива, рейтинг АЗС, новые события контроля, АЗС с проблемами связи |
| **Топливо** | продажи по видам топлива, как заправляются (полный бак / на литры / на сумму), объёмы налива, оплата, цены по дням и реакция спроса на каждое изменение цены, загрузка рукавов ТРК, отпуск без оплаты |
| **Спрос** | тепловая карта «день недели × час» для топлива и магазина, профили по часам и дням недели, тренд, прогноз на 14 дней, месяцы |
| **Товары** | группы и товары, ABC/XYZ и матрица с рекомендациями, запасы (на сколько дней хватит, когда закончится, сколько заказать, неликвид), магазин относительно топлива по часам, возвраты и списания |
| **Финансы** | выручка, валовая маржа (топливо, магазин), маржа на литр, наценка, покрытие себестоимостью, деньги по дням (наличные, безнал, выдача из кассы) |
| **План-факт** | месячные планы по АЗС, выполнение, отставание от графика, прогноз на конец месяца |
| **Запасы топлива** | остаток каждого резервуара, расход в день, на сколько дней хватит, до какого числа заказать, рекомендуемый объём, история остатков, приёмы топлива с недостачами |
| **Контроль** | события (аномалии) с важностью и ссылкой на смену, правила с порогами, уведомления в Telegram |
| **Смены** | список смен с итогами, карточка смены (тот же отчёт, что в Топазе), статистика по операторам |
| **АЗС** | сравнение АЗС по показателям, состояние агентов, здоровье ПК АЗС (место на диске, размер и рост базы Топаза, точность часов), название, часовой пояс, регион; **обновление агентов** (владелец): версия, раскатка, группы |
| **Данные** | все операции (отпуски, чеки, приёмы, касса, журнал событий) с поиском и выгрузкой в CSV для Excel |
| **Настройки → Виды топлива** | эталонный справочник видов топлива и сопоставление с ним топлива каждой АЗС |
| **Себестоимость** | закупочные цены сливов топлива (средняя по резервуару, список сливов без цены), цена остатка на дату, цены товаров, загрузка из Excel |

## Справочник видов топлива

Одно и то же топливо в Топазе на разных АЗС называется по-разному. Все сводные отчёты, сравнение АЗС и фильтр по топливу работают по **эталонным видам** из справочника (**Настройки → Виды топлива → Справочник**). Начальный набор: АИ-92, АИ-95, АИ-98/100, ДТ, СУГ, Метан, Прочее. Владелец может:
- добавлять виды (например, «АИ-95 премиум», «ДТ зимнее»);
- переименовывать их и менять порядок;
- скрывать виды. Скрытый вид не предлагается для новых сопоставлений, но уже сопоставленное топливо остаётся в нём;
- удалять неиспользуемые виды. Вид «Прочее» удалить или скрыть нельзя: в него попадает нераспознанное топливо.

**Сопоставление** (вкладка «Сопоставление»). Когда подключается новая АЗС или в Топазе появляется новое топливо, сервер сам предлагает вид:
1. **как на других АЗС** — вид, подтверждённый для такого же названия. Регистр, пробелы, дефисы и точки не важны: «Аи-95 Ultimate» = «АИ 95 ultimate»;
2. **по названию** — 92/95/98/100, ДТ/дизель, СУГ/пропан/газ, метан/КПГ;
3. иначе — «Прочее».

Пока топливо не подтверждено:
- отчёты используют предложенный вид;
- в меню у «Настроек» горит счётчик;
- на «Обзоре» владелец видит подсказку;
- в «Контроле» появляется событие «Топливо АЗС не сопоставлено со справочником».

Подтвердить можно по одному или кнопкой «Подтвердить все предложения» (для всех АЗС или выбранной). Событие закрывается само, когда всё подтверждено. Изменение сопоставления сразу меняет все отчёты, включая прошлые периоды. Сопоставляет только владелец, все действия пишутся в журнал.

## Подключение АЗС

Агент ставится на АЗС установщиком `TopazAgent-Setup-<версия>.exe` — двойной клик, название АЗС, без ключей — и сразу присылает **заявку на подключение**. Заявка появляется в **АЗС → Подключение**:
- у пункта «АЗС» в меню горит счётчик;
- на «Обзоре» показывается подсказка;
- в «Контроле» появляется событие, в Telegram приходит сообщение.

В заявке видно:
- название, имя ПК, IP, версию агента и Windows;
- «агент ждёт N с назад»;
- сведения из базы Топаза: последняя смена, оператор, виды топлива;
- для повторного подключения — какая АЗС была раньше.

**Одобрение (только суперадминистратор):**
1. Спросить у установщика **код подтверждения**: он показан в конце установки и в выводе `TopazAgent.exe check`. Код из заявки не подставлять — смысл именно в сверке.
2. Нажать «Одобрить», ввести код, выбрать:
   - «новая АЗС» (можно поправить название) и **организацию**, которой она принадлежит;
   - «существующая АЗС» — переустановка или новый ПК: история сохраняется.
3. В течение минуты агент получит доступ и отправит всё, что накопил с момента установки.

Также можно:
- **«Отклонить»** — по желанию с блокировкой адреса на 30 дней;
- в «Состоянии и настройках» в меню АЗС: **«Заблокировать»** (доступ пропадает сразу, история остаётся), **«Разблокировать»**, **«Перевыпустить доступ»** (агент пришлёт новую заявку, её нужно одобрить как существующую АЗС).

Все действия пишутся в журнал. Необработанные заявки истекают через 14 дней.

## Обновление агентов

Раздел **АЗС → Обновление агентов**, только для суперадминистратора. Новая версия агента входит в обновление сервера. После `setup.sh` она появляется здесь, и агенты подтягивают её сами — подробности в [deploy/agent/README.md](../deploy/agent/README.md#автообновление).

- **Группы АЗС:**
  - **пилотная** — получает новую версию сразу;
  - **обычная** — через заданное число часов после появления версии (по умолчанию 24) и только если ни одна пилотная АЗС не сообщила об ошибке, а хотя бы одна обновилась успешно. Если пилотных нет — просто после задержки;
  - **не обновлять** — только кнопкой «Обновить сейчас».
- **Управление:** выключатель автообновления, пауза, задержка, «Обновить все сейчас» (без ожидания пилотных), «Обновить сейчас» для одной АЗС.
- **Отчёт агентов:** для каждой АЗС видны версия, платформа и состояние последнего обновления (скачивает / устанавливает / обновлено / ошибка с причиной).
- **Ошибки:** неудачное обновление создаёт событие «Обновление агента не удалось» в «Контроле». Агент при этом уже вернулся к прежней версии и работает.
- Агенты версий 1.0 и 1.1 отмечены «вручную»: их нужно один раз обновить, запустив на АЗС установщик новой версии.

## Определения показателей

Все суммы — по итоговой стоимости после скидок (`flOrders.Amount`), как в отчётах Топаза. Правила сверены с реальным экспортом Топаза (см. [topaz-schema.md](topaz-schema.md)).

| Показатель | Как считается |
|---|---|
| Выручка топливо | Σ `Amount` отпусков |
| Продано топлива, л | Σ объёма отпусков с объёмом > 0 и оплатой. **Тех. прокачки и переливы** (`Amount = 0`) сюда не входят, они показаны отдельно как «отпуск без оплаты», но входят в расход резервуара |
| Заказы | отпуски с объёмом > 0 и оплатой |
| Прерванные наливы | отпуски с объёмом 0 (Топаз считает их в «кол-ве заказов» своего отчёта) |
| Средний налив | литры / заказы |
| Средний чек топливо / магазин | выручка / заказы; выручка магазина / число чеков |
| Способы оплаты | доля выручки топлива по способам: наличные, банковская карта, по договору (ведомости), топливные карты; «Доля безнала» — всё, кроме наличных. Способ — у **вида оплаты** АЗС: по названию (`payment_category_guess`: «ведом», «договор» → договор; «e1», «топливн» → топливные карты; «банк», «терминал», «сбп», «сбер» → карта; «налич» → наличные; «карт» → карта; «прокачк», «перелив» → без оплаты), владелец может исправить (Настройки → Виды оплаты). Продажа с пометкой Топаза «Б» / суммой безнала на наличном виде оплаты — карта. Пометка «Б» есть не на всех АЗС, поэтому одна она не решает |
| Скидки | поле скидки Топаза (`AmountDiscount`), а если оно пустое и цена заказа выше цены колонки — литры × (цена заказа − цена колонки): так проявляется скидка дисконтного вида оплаты |
| Цена (отпуска, смены) | цена со скидкой, которую заплатил клиент: цена колонки Топаза (`PricePump`, по ней посчитана сумма), а если её нет — цена заказа (`Price`, в выгрузке смены Топаза — `OrigPrice`). SQL `fuel_price_paid(price, price_pump)`; цена без скидки показывается рядом зачёркнутой. В сводке смены — максимум по группе |
| Себестоимость топлива | литры × **средняя цена литра в резервуаре** в момент продажи. При сливе с ценой: средняя = (остаток до слива × средняя + литры слива × цена слива) / (остаток до слива + литры слива); остаток до слива — по книге Топаза (начало смены + более ранние сливы − отпуск из резервуара до слива). Слив без цены не меняет среднюю; первый слив с ценой оценивает уже лежащий остаток по своей цене; «цена остатка на дату» задаёт среднюю всех резервуаров топлива. Литры слива — `DocVolume` (масса и плотность Топаза не используются). Расчёт — `Processing/FuelCostAverager`, таблица `fuel_cost_avg` |
| Себестоимость товара | так же: цена товара для АЗС или «для всех АЗС», действовавшая в момент продажи |
| Валовая маржа | выручка − себестоимость, **только по продажам с известной ценой**. Рядом показано покрытие. Организация с режимом «Маржа без НДС» (Настройки → Маржа и НДС): из выручки продаж **с фискальным чеком** вычитается НДС по ставке организации (выручка × ставка / (100 + ставка)), закупочные цены вводятся без НДС |
| Покрытие | доля проданных литров (или выручки магазина), для которых введена себестоимость |
| Маржа на литр | маржа топлива / литры с известной ценой |
| Наценка | (выручка − себестоимость) / себестоимость |
| Как заправляются | «полный бак» — заказанный объём 0; «на литры» — целое число литров, равное заказанному; «на сумму» — оплачена круглая сумма (кратна 100 ₽) за нецелый объём |
| Реакция на цену | средние литры в день за 14 дней до и после изменения цены; эластичность = изменение объёма, % / изменение цены, %. Это оценка: на спрос влияют и сезон, и погода |
| Тепловая карта | среднее за один день: сумма за период / число таких дней недели в периоде |
| Прогноз | для каждого будущего дня — среднее за 4 последних таких же дня недели × тренд (√ отношения последних 14 дней к предыдущим 14, в пределах ±20%) |
| ABC | товары по убыванию выручки: A — пока накопленная доля до 80%, B — до 95%, C — остальное |
| XYZ | коэффициент вариации недельных продаж за полные недели периода: X < 10%, Y < 25%, Z — больше. Нужно не меньше 4 полных недель |
| Остаток товара | сумма регистра товаров (`rgItemRests`) на текущий момент; в карточке смены — на момент закрытия смены. В «Товарах» позиции с остатком ≥ 10 000 (условный «бесконечный» остаток Топаза для напитков: 99 999, 999 999…) в список остатков не входят |
| Запас товара, дней | остаток / средние продажи в день за последние 28 дней. Рекомендуемый заказ = продажи в день × N дней × 1,2 − остаток |
| Неликвид | товар с остатком, который не продавался заданное число дней (по умолчанию 30) |
| Остаток в резервуаре | по учёту: начало текущей смены + приход − отпуск. Замеров уровня при закрытии смен в Топазе нет |
| Хватит на, дней | (остаток − max(минимум, мёртвый остаток)) / средний расход за 28 дней (включая тех. прокачки) |
| Заказать до | сегодня + дней запаса − срок поставки − страховые дни |
| Рекомендуемый заказ топлива | 95% вместимости − остаток, ожидаемый к приходу машины; округлено до 100 л |
| План: отставание | факт − план × (прошедшие дни / дни месяца) |
| План: прогноз | факт + прогноз на оставшиеся дни месяца |

## Контроль

Правил — 23. Они проверяются каждые 5 минут по данным за последние 30 дней. На один объект (смену, рукав, приём, резервуар за день) создаётся одно событие, повторов не бывает. Пороги и важность владелец меняет в разделе **Контроль → Правила**.

| Правило | Важность по умолчанию | Порог |
|---|---|---|
| Разрыв счётчика ТРК между сменами — признак отпуска мимо учёта. Сравнивается с концом смены с номером на единицу меньше; пока её нет (история АЗС ещё загружается), сравнивать не с чем | критично | 0,5 л |
| Счётчик ТРК за смену ≠ сумма отпусков по заказам. Переход счётчика через 999 999,99 → 0 учитывается. События по счётчикам, которые данные больше не подтверждают (догрузились смены или заказы), удаляются автоматически | внимание | 1 л |
| Много прерванных наливов в смене (не меньше 5) | внимание | 8% |
| Большой отпуск без оплаты за смену | внимание | 50 л |
| Много скидок в смене | информация | 3% выручки |
| Цена отпуска не сходится: клиент заплатил больше цены заказа, сумма ≠ литры × цена колонки (больше 1 ₽) или цену снизили мимо скидок Топаза при недисконтном виде оплаты (Настройки → Виды оплаты; дисконтные определяются по названию). Неоплачиваемые отпуски не проверяются | внимание | 0,01 ₽ |
| Недостача при приёме топлива, отрицательный приём | внимание | 0,5% |
| Смена не закрыта | внимание | 30 ч |
| Топливо заканчивается | критично | срок поставки + страховой запас |
| Товар закончился (продавался последние 28 дней) | информация | — |
| АЗС не на связи (закрывается автоматически, когда связь восстановится) | критично | 15 мин |
| Данные не принимаются (отклонённые или необработанные пакеты) | критично | — |
| Топливо АЗС не сопоставлено со справочником (закрывается автоматически после подтверждения) | информация | — |
| Обновление агента не удалось (агент вернулся к прежней версии) | внимание | — |
| Не введена цена слива (сливы за 30 дней; закрывается автоматически, когда цену ввели) | внимание | 24 ч |
| Недостача по замеру: при закрытии смены замер (уровнемер `dcTanks.LevelGauge` или ручной ввод, `flSesTanks.FactFuelVolume`) меньше учёта Топаза | внимание | 20 л |
| Излишек по замеру: замер больше учёта — обычно слив без прихода в Топазе; в «Потери по замерам» не входит | внимание | 200 л |
| Мало места на диске АЗС: на диске с базой Топаза или системном (с прогнозом, когда место закончится; закрывается автоматически) | внимание | 2 ГБ |
| Часы ПК АЗС сбились: время ПК с учётом пояса Windows отличается от точного (закрывается автоматически) | внимание | 5 мин |
| АЗС ожидает подключения: новый агент прислал заявку (закрывается, когда по заявке принято решение) | внимание | — |
| Из базы АЗС удалены данные старых смен: агент прислал удаление строк смены, закрытой больше `Topaz__HoldDeletesAfterDays` (3) дней назад (обычно свёртка базы). Удаление не применяется, строки лежат в `held_deletes`; одно событие на АЗС и день, число записей обновляется; закрывается само, если строки вернулись | критично | — |

**Уведомления в Telegram:**
1. Создайте бота у @BotFather.
2. Впишите токен в `TOPAZ_TELEGRAM_BOT_TOKEN` и перезапустите сервис.
3. В разделе **Контроль → Уведомления** добавьте чат (chat id) и выберите минимальную важность. Кнопка «Тест» проверяет связь.

События отправляются сразу, одним сообщением на проверку, и только за последние сутки: при первом запуске история не рассылается. Утром в 9:00 по Москве приходит сводка за сутки. Токен в логи не пишется.

## Как устроено (для разработчиков)

- **Код:**
  - фронтенд — `web/` (Vite, React 18, TypeScript, Ant Design, TanStack Query, ECharts);
  - API — `src/Topaz.Central/Ui/*Endpoints.cs` под `/api/v1/ui`;
  - сборка: Dockerfile собирает `web/` и кладёт результат в `wwwroot`.
- **Версия и обновление открытых вкладок:**
  - Dockerfile передаёт `VERSION` (версию тега) и в сборку веба (`__APP_VERSION__`), и в сборку сервера.
  - Сервер ставит заголовок `X-Topaz-Version` на все ответы `/api/v1/ui`. Если он отличается от версии страницы, вкладка показывает плашку «Сайт обновлён», а при переходе в другой раздел перезагружается (`web/src/lib/appVersion.ts`, `components/appUpdate.tsx`).
  - Ошибка загрузки кода раздела вызывает одну перезагрузку, не чаще раза в 30 с; остальные ошибки отрисовки ловит error boundary.
  - `index.html` отдаётся с `no-cache`, `/assets/*` — с `immutable`. Отсутствующий файл (`/assets/…` или путь с расширением) получает 404, а не страницу (`WebHostingTests`).
- **Ограничение доступа к АЗС** централизовано в `StationScope` (АЗС организации пользователя), общий фильтр — в `UiFilter`.
- **Соединение с базой** в UI-эндпоинтах — только `UiDb`: отдельный пул под ролью `topaz_ui`, на каждое соединение ставятся `app.stations`, `app.org`, `app.platform`, и политики RLS отсекают чужие строки. Системный пул (`UiDb.System`) — только для платформенных действий суперадминистратора. Новое представление должно быть `security_invoker = true`, новая таблица с данными АЗС — со своей политикой (`TenantIsolationTests` проверяют оба правила и перебирают все GET-маршруты).
- **Источники данных отчётов:**
  - длинные периоды (KPI, графики по дням, неделям и месяцам, сравнение АЗС, ABC, финансы, планы) читают дневные агрегаты `agg_fuel_daily`, `agg_shop_daily`, `agg_shop_receipts_daily`. Их пересчитывает `RollupRefresher` по меткам `rollup_dirty`, которые обработчик пакетов ставит в той же транзакции. Себестоимость тоже считается при пересчёте, поэтому её изменение помечает АЗС на полный пересчёт;
  - детализация (часы, рукава, наливы, карточка смены) читает исходные таблицы за выбранный период.
- **Скорость** (5 демо-АЗС, полгода, одно ядро): «Обзор» за полгода ~0,2 с, «Финансы» ~0,1 с, «Товары» ~0,3 с, «Топливо» за 3 месяца ~0,8 с. Запросы одной страницы выполняются параллельно, на многоядерном сервере быстрее.
- **Демо-данные:** `dotnet run --project tools/DemoData -- --server http://localhost:8080 --admin-token <TOPAZ_ADMIN_TOKEN> --stations 5 --days 180`.
- **Тесты:**
  - серверные — `tests/Topaz.Central.Tests` (`UiTests`, `AnalyticsTests`, `MoneyTests`, `ControlTests`, `TenantIsolationTests`);
  - фронтенд — `cd web && npm test`;
  - e2e — `npx playwright test` против запущенного стека с демо-данными (`E2E_BASE_URL`, `E2E_LOGIN`, `E2E_PASSWORD`, `E2E_PERIOD`).
