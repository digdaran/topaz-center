# База данных «Топаз АЗС»: что известно

Изучена копия рабочей базы одной АЗС (2026-10-31): `ProgConfig.Version = 3.15.20.12096`, Firebird **2.5.9**, ODS 11.2, кодировка UTF8, страница 8 КБ.
Сам файл базы в репозиторий **не попадает** (`*.fdb` в `.gitignore`): в нём реальные данные АЗС.

## Общие особенности

- **117 пользовательских таблиц**, 23 процедуры, 112 генераторов, около 400 триггеров.
- Имена в **смешанном регистре в кавычках**: `"flOrders"`, `"SessionID"`. Без кавычек запрос не сработает.
- Префиксы: `dc*` — справочники, `fl*` — топливо, `tr*` — товарные документы, `rg*` — регистры (движения), `cm*` — касса, `sys*` — системные таблицы и журнал.
- Домены: `TID` = INTEGER (ключи), `TCurrency`/`TVolume` = NUMERIC(15,2), `TQuantity` = NUMERIC(15,3), `TDensity` = NUMERIC(15,4), `TBoolean` = INTEGER 0/1, `TDateTime` = TIMESTAMP (**местное время без пояса**), `TXmlBlob` = BLOB TEXT.
- В транзакционных таблицах **нет даты изменения**. `modifyDate` есть только у части справочников, и это служебное поле синхронизации с офисом.
- Строки меняются после вставки: заказ `flOrders` создаётся при старте налива и обновляется по окончании.
- ID в `flOrders` и `sysEvents` растут вместе со временем (проверено на всех строках).
- Триггеры Топаза вызывают UDF (`MD5`), поэтому вставка или изменение через сторонний клиент без библиотек Топаза падает. Агенту это не мешает: он только читает.
- Строк, которые ссылаются на несуществующую смену, нет (проверено для `flOrders`, `rgCashes`, `rgFuels`, `trFastTradeH`).

## Что выгружается

Полный список — `src/Topaz.Agent/datasets.json` (105 таблиц). Его можно править без пересборки агента: таблица, которой нет в другой версии Топаза, пропускается с предупреждением в логе.

**Не выгружаются:** служебные таблицы синхронизации и журналы изменений (`sysDataChangeLogs`, `sysDataChangeLogTables`, `sysDataChangeTypes`, `syncData`, `syncGlobalErrors`, `sysExportExceptions`), служебные (`sysModules`, `sysConsts`, `sysDescriptions`, `sysUsersLaw`), таблицы без PK (`rgDCWebOfficeTransaction`, `rgOEMediaTransaction`).

**Исключённые колонки:** `dcAgents.Password`, `sysUsers.PswHash`, `sysUsers.Psw`, `sysUsers.SecurityData`, `dcPaymentModes.Config`.

## Сверка с отчётами Топаза (2026-10-31)

Сверка шла с двумя XML-экспортами из самого Топаза той же АЗС: экспорт данных за октябрь и агрегированный экспорт смены 80. Источником для сравнения служила центральная БД, загруженная агентом, то есть проверялась вся цепочка «Топаз → агент → сервер». Скрипты лежат в `tools/reconcile/`.

| Проверка | Результат |
|---|---|
| Экспорт за период (`DataPacket`): 33 таблицы, 1043 строки, около 30 тыс. значений | 1043/1043 строки совпали поле в поле |
| Экспорт смены 80, пересчёт каждого раздела из строк | 1083 проверки, 0 расхождений |
| Экспорт смены 80 из SQL-представлений центра (`v_shift_*`, `item_rests_at`) | 108 проверок, 0 расхождений |

Чувствительность скрипта проверена: подмена одного значения на 1 копейку обнаруживается.

### Откуда берутся цифры отчёта смены

| Раздел отчёта | Источник в БД | Правило |
|---|---|---|
| `Session` | `sysSessions` | `SessionNum`, время начала и конца, `UserName` |
| `Tanks` | `flSesTanks` (+ `dcTanks.DeadRest`, `DeadRestLiter`) | все резервуары смены, даже без отпуска. `EndFact*` пусты, если замеры при закрытии не вводились (`FactFuelVolume IS NULL`) |
| `Hoses` | `flSesHoses` | `HoseNum` = `ThroughNumber`, `StartCounter`/`EndCounter` = `StartAdder`/`EndAdder`. Разница счётчиков = сумма `flOrders.Volume` = `flSesTanks.PumpVolume` (2080,25 л) |
| `OutcomesByRetail` | `flOrders` | группировка по резервуару, рукаву, топливу, **названию** вида оплаты, `Remark`, агенту и карте. `OrderCount` включает заказы с нулевым объёмом (прерванный налив), `OrigPrice` = `Price` |
| `OutcomesByRetailDetail` | `flOrders` | одна строка на заказ, все поля 1:1 |
| `ItemOutcomesByRetail` | `trFastTradeH` + `trFastTradeD` | группировка по товару, виду оплаты, контрагенту и `IsReturn`; `Amount` = Σ `Total`, `PriceFastTrade` = `Price` |
| `ItemOutcomesByPaysheet` | то же | **`Price` здесь — это Σ цен строк, а не цена** (11 шт × 150 → `Price=900` при 6 строках). Использовать нельзя |
| `CashFlow` | `rgCashes` | Σ `Amount` по `DocTypeID` и `CashID`; `Remark` берётся из `cmCashReceipt`/`cmCashOut`. В сумме за смену получилось 0: всё выдано |
| `TradeDocsOutActs` | `trOutActH`/`D` | акты с `DateDoc` внутри смены |
| `ItemRests` | Σ `rgItemRests.Quantity` с `Date ≤ EndDateTime` смены | **остаток на момент закрытия смены**, а не на момент экспорта (34/34 против 27/34) |

### Что выяснилось о данных

- **Наличные или безнал определяются не по виду оплаты.** Признак безнала — `flOrders.Remark = 'Б'` вместе с `AmountCashless > 0`. Заказ с видом оплаты «Терминал Альфабанк» без «Б» проведён как наличные: он попал в `rgCashes` на кассу «ФР Штрих-М». В центре для этого есть вычисляемое поле `fuel_sales.payment_kind` (`cash` / `cashless` / `mixed` / `none`).
- **`AmountCash`/`AmountCashless` — это предоплата до скидки, а `Amount` — итоговая стоимость.** Пример: залив на 1500 ₽ по 48 ₽ со скидкой 1 ₽/л даёт `AmountCash=1500`, `Amount=1499,77`, `AmountDiscount=31,91`. Выручку считать по `Amount`. Касса (`rgCashes`) тоже ведётся по `Amount`.
- **Одно название вида оплаты бывает у нескольких ID**: «НАЛИЧКА» = 109 и 115, «СКИДКА» = 110, 112 и 113. Отчёты Топаза группируют по названию. `ExtCode` у видов оплаты пустой, так что сопоставление с 1С придётся настраивать в центре.
- `PMID` у вида оплаты — GUID платёжного модуля (драйвера), а не идентификатор вида.
- «Тех. прокачка» и «Переливы» имеют `Amount = 0`, но входят в отпуск из резервуара и в счётчики ТРК.
- Около 10% заказов с `Volume = 0` (152 из 1555) — прерванные наливы. Топаз считает их в `OrderCount`.
- `StatusOrder = 0`, `OrderSource = -1`, `CardType = -1` у всех 1555 заказов: на этой АЗС карты и внешние источники заказов не используются, смысл значений по этим данным не установить.
- **Экспорт за период режет по времени операции, а не по сменам.** Из смены 60 (30.09–01.10) в экспорт за октябрь попали только 13 из 32 отпусков, те, что после 01.10 00:00. Справочники экспортируются только в использованной части (1 резервуар из 5). Чтобы центральные отчёты «за период» совпадали с Топазом, фильтровать надо по `sold_at`/`doc_at`, а не по сменам.
- Ошибка в справочнике: у «Кофе МАЛЫЙ» `dcItems.FullName = 'Кофе БОЛЬШОЙ'`. Отчёты показывают это как есть.
- Огромный остаток «Кофе МАЛЫЙ» (999 906) — по-видимому, условный бесконечный остаток для товара собственного производства.
- **Безопасность:** собственный экспорт Топаза за период содержит `sysUsers.PswHash` и `Psw`. Передавать такие файлы наружу нельзя. Агент эти колонки не выгружает.

## Открытые вопросы

- Смысл `StatusOrder`, `OrderSource`, `CardType`: нужна АЗС, где работают топливные карты или ведомости.
- Как `rgCashes` проводит смешанную оплату (наличные + безнал в одном заказе): в изученных данных таких заказов нет.
- Нужен ли `CardCode` (номер топливной карты) в центре в открытом виде. Сейчас он передаётся по TLS как есть и в логи не пишется.
- Можно ли открыть доступ к Firebird АЗС по сети (сейчас агент ставится на тот же ПК и ходит на `127.0.0.1:3050`).
